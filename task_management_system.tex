\subsection{Task Management System}

The Task Management System is a comprehensive feature that allows users to organize, schedule, and track their tasks efficiently. The system follows the MVVM (Model-View-ViewModel) architecture pattern and implements a centralized repository pattern with singleton design for data management.

\subsubsection{Architecture Overview}

The task management system is built using the MVVM (Model-View-ViewModel) architecture pattern, which provides a clear separation of concerns and enables efficient data binding between the UI and business logic:

\begin{itemize}
    \item \textbf{Model Layer}: Consists of \texttt{CalendarTask} and \texttt{CalendarTasklist} data classes that represent the core entities
    \item \textbf{ViewModel Layer}: \texttt{CalendarViewModel1} manages the UI state and coordinates between the View and Repository
    \item \textbf{View Layer}: Compose UI screens that observe state changes and react to user interactions
    \item \textbf{Repository Layer}: \texttt{CalendarRepository1} implements the singleton pattern to provide centralized data access
\end{itemize}

The system utilizes a singleton repository pattern through \texttt{CalendarRepository1}, which maintains \texttt{mutableStateListOf} collections for tasks and task lists. This design ensures real-time UI updates across all screens when data changes occur, as the Compose UI automatically recomposes when the observable state changes.

\subsubsection{Data Management and Real-Time Updates}

\textbf{Singleton Repository Pattern:}
The system implements \texttt{CalendarRepository1} as a singleton that maintains:
\begin{itemize}
    \item \texttt{mutableStateListOf<CalendarTask>} for tasks
    \item \texttt{mutableStateListOf<CalendarTasklist>} for task lists
    \item API integration for data persistence
    \item Automatic local state synchronization
\end{itemize}

\textbf{Real-Time UI Updates:}
The MVVM architecture enables automatic UI updates through:
\begin{itemize}
    \item \texttt{CalendarViewModel1} exposing repository state via properties
    \item Compose UI observing \texttt{mutableStateListOf} collections
    \item Automatic recomposition when data changes occur
    \item Consistent state across all screens without manual refresh
\end{itemize}

\textbf{API Integration:}
The system provides robust API integration with:
\begin{itemize}
    \item RESTful API calls for CRUD operations
    \item Optimistic UI updates with rollback capability
    \item Error handling and user feedback
    \item Offline capability with local state management
\end{itemize}

\subsubsection{Navigation Flow and Data Passing}

The navigation system implements a hierarchical flow:

\begin{enumerate}
    \item \textbf{Month Screen} $\rightarrow$ Daily Schedule (with date parameter)
    \item \textbf{Daily Schedule} $\rightarrow$ Task Action Selection (preserving date context)
    \item \textbf{Task Action Selection} $\rightarrow$ Add Task/Add Task List screens
    \item \textbf{Add Task List} $\rightarrow$ Tasks in Task List (with task list ID)
    \item \textbf{Tasks in Task List} $\rightarrow$ Task Detail (with task ID)
    \item \textbf{Task Detail} $\rightarrow$ Edit Task (preserving task data)
\end{enumerate}

The navigation system preserves context through URL parameters and leverages the singleton repository to maintain data consistency across screen transitions, ensuring that users never lose their work or context when navigating through the application.
